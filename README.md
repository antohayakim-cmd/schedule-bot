# Telegram-бот расписания ННГУ

Python 3.10+. Новый самостоятельный проект на основе описания API и парсера campuspilot3. Построения маршрутов, геокодирования и транспортных зависимостей здесь нет. Старый проект не изменяется.

## Использование

- Напишите `расписание` **без слеша**. Регистр и пробелы по краям не важны.
- Бот показывает сегодня и завтра, включая дни без занятий.
- Под ответом расположены кнопки с датами от послезавтра до воскресенья текущей недели включительно. В субботу и воскресенье дополнительных дат нет, так как сегодня и завтра уже показаны.
- Кнопка «Сегодня и завтра / обновить» возвращает начальный вид и повторно запрашивает API.
- `старт` или `помощь` показывают подсказку и клавиатуру. Стандартная Telegram-кнопка Start (`/start`) тоже поддерживается; для расписания слеш не нужен.
- Даты рассчитываются по Москве. Группа по умолчанию — `50793`.

## Запуск в Windows (PowerShell)

Откройте терминал в этой директории:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
.\.venv\Scripts\python.exe bot.py
```

Если окружение уже создано, первые две команды можно пропустить. В `.env` заполните `TELEGRAM_BOT_TOKEN` токеном **нового бота**, созданного через @BotFather. Токен не публикуйте. `TELEGRAM_CHAT_ID` не требуется: бот отвечает в чат, откуда пришёл запрос.

Переменные:

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| TELEGRAM_BOT_TOKEN | Токен Telegram | Обязательна |
| UNN_GROUP_ID | ID группы RUZ | 50793 |
| RUZ_BASE_URL | Базовый адрес API | https://portal.unn.ru/ruzapi |

`.env` читается из директории проекта, независимо от текущей директории терминала. Системные переменные имеют приоритет.

Процесс должен работать постоянно: используется long polling. Завершение — Ctrl+C. Для каждой учётной записи бота запускайте один экземпляр. При использовании в группах Telegram обычные текстовые сообщения должны быть доступны боту: настройте privacy mode в @BotFather либо выдайте права администратора. В личном чате дополнительных настроек не требуется.

## API

Источник контракта — `app/schedule.py`, `app/parser.py` и `app/config.py` из campuspilot3:

```text
GET https://portal.unn.ru/ruzapi/schedule/group/50793
    ?start=YYYY-MM-DD&finish=YYYY-MM-DD&lng=1
```

Авторизация для этого запроса в исходном проекте не предусмотрена. Ожидается JSON-массив занятий: `date`, `beginLesson`, `endLesson`, `discipline`, `lecturer`, `kindOfWork`, `building`, `auditorium`. Поддерживаются альтернативные названия полей из старого парсера и три формата дат. Пустой массив означает отсутствие занятий; сетевые ошибки и полностью неразбираемый непустой ответ показываются как ошибка загрузки.

Сегодня и завтра запрашиваются одним запросом. При выборе даты API запрашивается заново. Текст выводится без Markdown, чтобы символы в названиях предметов и фамилиях не ломали сообщение. Длинные ответы делятся на несколько сообщений; кнопки находятся под последним.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Проверки используют подставной HTTP-транспорт и Telegram-объекты; настоящий токен им не нужен. Проверка реального диалога в Telegram требует настроенного токена и запущенного процесса.
